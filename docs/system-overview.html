taktloop — system overview of the MVP factory (taktloop builds taktloop)

① Every executor talks to the core only through MCP/API, always with a token. With the bridge skill it pulls work: list_open_steps → claim_step → get_step_context (names the skill to use) → work → complete_step with evidence.
② For steps marked push, the taktloop orchestrator starts a headless harness run itself (nobody has to be polling).
③ The headless builder pushes branches with git and uses GitHub's remote MCP server (PRs, runs), with its own role-scoped GitHub credential. taktloop is not in between.
④ Harnesses read/write tickets through the local stand-in MCP server.
⑤ Executors get their core tokens from the dev issuer; the core only fetches its public keys (JWKS) to validate them.
⑥ The gate checker in the core is itself an MCP client: it calls GitHub's MCP server with plain code to verify "CI green", never trusting the agent's word.
⑦ The core is also an MCP client of the ticket stand-in: it reads ticket status with its own credential to detect out-of-sync tickets (escalated to the factory owner) and for gate checks that depend on a ticket.

Terms

Factorythis setup: one core + config + bindings, here "taktloop builds taktloop"
Task / stepa task is one capability request; it moves through steps (design, plan, build, …), each owned by one role
Rolepermission + responsibility for a step (builder, reviewer, approver …), read from the token
Executorwhoever does a step: a harness run, a human, or a script
Bindingconfig line "role X is done by executor Y"
Harnessan existing agent runtime (Claude Code). taktloop has no agent loop of its own
Skillinstructions loaded into a harness. Superpowers = the work skills; bridge skill = how to talk to the core
Pluginan external tool's MCP server + the skill that explains it (incl. its auth). Ships with templates
Agent step / code stepagent step: an LLM in a harness does it. Code step: the orchestrator makes one declared MCP call itself
Gatecondition to leave a step: human approval in the core, agent verdict, or a hard gate checked by plain code
taktloop orchestratorpart of the core: transitions, pushes, stall watch, escalation; AI only when judgment is needed
