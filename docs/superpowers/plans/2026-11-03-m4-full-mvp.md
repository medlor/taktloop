# M4: the full MVP — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tickets that follow each task (stand-in process + hooks + out-of-sync check), triage routes with a park gate, live per-step workflow changes with versions, a startup availability check, a plain HTTP API, and a service/team setup split with short user docs.

**Architecture:** The core keeps state, rules and every *read* of the outside world (gate checks, sync checks, availability); it now also owns `workflow.yaml` (versioned snapshots in SQLite, a draft edited over MCP, the file rewritten on approval). The orchestrator stays the only actor: it runs code steps (now including `open_ticket`), pushes the headless triage bot, fires hooks from the core's event feed and triggers sync checks. The ticket stand-in is its own MCP server process that knows nothing about tasks.

**Tech Stack:** Python ≥ 3.12, uv, `mcp` ≥ 2.3 (`MCPServer`, streamable HTTP, Starlette underneath), `pyyaml`, `pyjwt[crypto]`, SQLite, pytest; Claude Code CLI for headless runs.

**Spec:** `docs/superpowers/specs/2026-11-03-m4-full-mvp-design.md` (approved). M1–M3b designs hold where it is silent.

## Global Constraints

- Line budget: `wc -l $(find src -name '*.py') | tail -1` **≤ 4,300** (today 2,898, so **≤ +1,402**; the tasks' allowances add up to ~1,100). No module over ~300 lines. Put the running total in each commit body (`src total: N`). **If the count heads over the cap, stop and ask @Tobias**; drop nothing silently.
- Direct runtime dependencies unchanged: `mcp`, `pyyaml`, `pyjwt[crypto]`. uv only (`uv run pytest`, `uv run taktloop …`). English docs; product name "taktloop".
- The core never writes to the outside world; the orchestrator never decides a gate or a sync verdict. No network call while a SQLite transaction is open.
- No token (taktloop, GitHub, tickets) in logs, events, run logs, hook stdin, hook env or `workflow.yaml`.
- Reserved targets: `done`, `cancelled`. Reserved step names: the same.
- Ports: issuer 8766, core 8765, tickets **8767**. Ticket token env: **`TAKTLOOP_TICKETS_TOKEN`**.
- Hook retries: **3 attempts**; command hook timeout **30 s**; sync default `every_minutes: 5`; availability re-check at most **once a minute**.
- Schema version **3**; a v2 database is refused with the existing "delete it to start fresh" message.
- Workflow file: `workflow.yaml` next to `factory.yaml` (key `workflow_file`), top-level keys `version`, `start`, `steps`, written with `yaml.safe_dump(data, sort_keys=False)` via temp file + `os.replace`.
- New roles: `triage`, `steward`, `factory_assistant` (and the existing `factory_owner`). New identities (template): `triage-bot` [triage], `assistant` [factory_assistant]; `orchestrator` gains `steward`.

## Review Focus

1. **A task without a ticket** (open_ticket not yet run, or a workflow without it): hooks and `check_sync` skip it silently, no error, no event. Pinned by `test_hook_skips_unresolved_placeholder` (Task 9) and `test_sync_skips_task_without_ticket` (Task 8).
2. **A workflow approved while a task is mid-flight**, including a code step the orchestrator holds: the task finishes on its own version's steps and `call`. Pinned by `test_running_task_stays_on_its_version` (Task 6) and `test_orchestrator_uses_the_steps_version` (Task 9).
3. **A hand-edited `workflow.yaml` that doesn't parse** (YAML error or graph problem) at `serve`: one-line error naming the problem, exit 2, no traceback. Pinned by `test_serve_refuses_broken_workflow_file` (Task 5).
4. **The ticket stand-in down while steps change**: hooks wait, then catch up in order; tasks keep moving. Pinned by `test_hook_waits_while_server_unavailable` (Task 9).
5. **`task create --route` with an unknown route or without `approver`**: refused before anything is created (no task, no ticket). Pinned by `test_create_with_route_refusals` (Task 4).
